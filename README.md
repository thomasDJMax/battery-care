# 电池管家 for macOS

原生 Mac 菜单栏电池养护工具，提供中文仪表盘和设置窗口。SwiftUI 负责界面，AppKit 提供菜单栏和设置窗口，IOKit 提供真实电池数据。仅在用户松手完成上限拖动、点击加减或其他充电操作后，更改系统充电上限。应用初次启动只读取当前充电管理状态。

## 1.3.5 后台权限与每日日期修复 · 2026-10-15

启用任一提醒后，后台电池采样会独立检查通知权限，正常最多每 60 秒读取一次；无需先生成提醒候选，也无需打开窗口。在系统设置中重新允许通知后，下次符合刷新间隔的采样会重新评估待提醒条件。回到前台、打开菜单和唤醒时可主动刷新；并发请求去重，失联请求超时后可重新读取，旧回调不能覆盖替代请求的结果。节流使用系统运行时间，调整系统日期不会延后权限恢复。

每日提醒统一使用当前时区的 Gregorian 民用日期作为持久化去重键。切换显示历法不会重复同日提醒，中国农历的普通月与闰月也不会再共用一个日期键。1.3.4 的 Gregorian 历史直接兼容；旧的非 Gregorian 键缺少绝对日期与闰月标记，保留记录但不猜测对应日期，因此这些旧记录在升级当日可能额外提醒一次。此后成功提交会保存稳定日期键。

只读自检新增后台权限节流、请求作废、历法切换、闰月、时区及旧 Gregorian 历史兼容检查。测试使用隔离偏好和通知提供者，保留原来的充电管理与登录项设置。

## 1.3.4 恢复与提醒修复 · 2026-10-15

修复旧临时恢复记录缺少原管理方式时无法退出的问题：在系统电池设置中手工确认后，可通过“已手动恢复”及二次确认结束旧记录，保留当前系统设置；系统读数未知或记录清理失败时继续保留记录和操作保护，不猜测原设置、不提交充电写入。

低电量与上限提醒改为在功能开启且条件满足时评估，仅成功提交后消费本次提醒；通知权限恢复后重新评估，提交失败至少间隔 60 秒重试。未知或过期读数不会被视为已经离开阈值，关闭功能和修改阈值会使旧候选失效。每日提醒保存成功日期，避免同一提醒分钟重启后重复；失败可在当日后续采样中限频重试。应用切回前台或显示设置窗口时重新读取系统登录项状态。

--self-test 增加提醒提交结果、重启去重、旧回调作废、缺失恢复标志的手工确认与清理失败、登录项状态刷新的隔离回归检查。检查不发送真实通知、不更改登录项，也不提交有效充电写入。

## 1.3.3 电量分档配色 · 2026-10-14

菜单栏图标和仪表盘电池图形采用同一套电量配色：0–24% 红色 `#EB5545`、25–49% 淡黄色 `#F3E098`、50–74% 黄色 `#F8D84A`、75–100% 绿色 `#68CE67`。颜色直接按档位切换，填充仍反映真实电量；充电或接电不会覆盖电量档颜色，未知电量使用中性空轮廓。充电时菜单栏文字继续以绿色表示充电状态。

通用设置中的菜单栏颜色开关改名为“按电量显示颜色”，沿用原有偏好；关闭后菜单栏使用系统对比色，仪表盘仍显示电量档颜色。`--render-status-qa` 覆盖未知电量、四档切换边界、充电闪电及明暗背景，另导出仪表盘电池图形。按钮、品牌与其他指标沿用原有薄荷配色。

## 1.3.2 界面品牌图标 · 2026-10-13

设置窗口左上角、菜单底栏和关于页统一改为薄荷绿电池与闪电图标。集中维护符号名称，macOS 13 使用兼容的旧符号名；玻璃材质与布局沿用 1.3.1。

## 1.3.1 窗口标题栏修复 · 2026-10-13

设置窗口使用完整内容区域承载玻璃背景，修复透明标题栏缺少背景、左上角窗口按钮悬在桌面上的问题。原生窗口按钮、安全区域和标题栏拖动继续由 AppKit 管理；养护与充电模块顺序保持不变。

## 1.3.0 液态玻璃 · 2026-10-13

菜单“充电上限”移到“快捷养护”前，设置仪表盘保持相同顺序。macOS 26 及以上使用原生 Liquid Glass 卡片和交互控件：电量概览、统计、充电、养护及设置模块统一透光与边缘高光；页面底层使用桌面磨砂材质，避免整页多重折射叠加。窗口保持透明，文字与薄荷色状态使用原有清晰层级。macOS 13–25 回退到磨砂材质，实体与柔化模式继续可选。

通用中的“毛玻璃”改名为“液态玻璃”，沿用 `glass` 偏好值。系统“降低透明度”启用时使用不透明表面；“减少动态效果”启用时保留静态材质并关闭玻璃互动。导出的 PNG 仅用于布局和对比度检查，真实背景透光与折射通过原生窗口验证。充电、监测、提醒与恢复逻辑不变。

## 1.2.0 界面重设计 · 2026-10-13

采用统一的石墨灰与薄荷绿配色，细边框、中性卡片和清晰文字层级。设置窗口改为侧栏导航，仪表盘以两栏区分实时状态与养护操作；电量大数字和电池图形仅显示一次，健康、循环、功率与应用活动分层展示。菜单浮层按电量概览、指标和快捷养护排序，80%／90%、临时充满与恢复系统管理入口优先呈现，详细滑块与其他模块可继续滚动查看。

滑块改为细轨道，操作按钮和选中状态统一使用薄荷色；快捷养护、自动保护与功率图去除大面积装饰色块。实体、毛玻璃和柔化材质继续可选，菜单栏绿色偏好与原有电池监测、充电操作、提醒和恢复流程保留。

设置窗口默认 1080×740，最小窗口 960×680；菜单浮层宽度仍为 410，按显示器可用高度定位。开发渲染覆盖六页设置、最小窗口、菜单、完整仪表盘、三种材质及明确隔离的充电／无读数示意状态；所有验证不提交有效充电操作。

## 1.1.0 综合优化 · 2026-10-13

- 电池读数和 App 活动独立采样。App 的 CPU 排名只在菜单仪表盘或设置的仪表盘可见时查询，最多每 15 秒一次；隐藏后停止查询，仅为实际显示的三行读取图标。电池继续按个人设置监测，进程查询超时不拖延电池更新。睡眠时暂停采样，唤醒后刷新，并丢弃旧任务的结果。
- 菜单栏电池图标按真实电量填充，未知电量保留空轮廓；绿色偏好继续保留，关闭颜色时由系统提供文字和模板图标对比度。相同读数不重复生成状态栏图像。
- 仪表盘增加更新时刻与刷新中反馈，将“当前耗电 App”更名为“当前活跃 App”，明确 CPU 活动不代表实际耗电份额；应用活动区分别显示读取中、空结果和失败状态。“充满预计”和“续航预计”根据充电状态区分。
- 充电上限与恢复系统管理都跟踪延迟回读，新提交的请求替换旧待确认请求。开启临时充满前，先原子保存并验证完整恢复点，再提交 100%；已有未确认的其他充电请求需先确认。
- 临时恢复记录保存在 `~/Library/Application Support/cn.local.iadente.remake/temporary-charge-session.json`。旧偏好记录仅在新记录验证后迁移；缺失管理方式或损坏记录保留并提示，不能猜测恢复方式。恢复的中间读数不清除恢复点，确认原设置并消费记录后至多提交一次自动完成通知。文件清理失败保留记录并重试，不重复写入已确认恢复的硬件设置。
- 校验充电上限、温度和低电量阈值、刷新间隔及计划时间中的非有限或越界值。容量只采用已知 mAh 字段，过滤异常整数并跳过无效占位值；功率历史不混合实测系统负载和电池放电估算来源。
- 电池供电时如系统负载传感器缺失，原有放电功率估算会明确标为“放电功率估算”，菜单栏功率加上 `≈`，避免将估算值误认为独立传感器实测。

本轮新增检查覆盖采样可见性、节流、睡眠与任务作废、异常指标、实际图标填充、延迟充电确认、恢复记录故障和偏好校验。检查使用只读硬件读取、隔离的测试提供者、UserDefaults 与临时文件，不提交有效充电写入、不更改登录项、不发送测试通知。

## 构建

需要包含 macOS 26 或更高 SDK 的 Xcode／Command Line Tools；应用运行下限仍为 macOS 13。Swift 包工具版本为 5.9，当前应用在 Apple Silicon macOS 27.0.1、Swift 6.4 上通过验证。

```sh
./build.sh                 # 只构建当前机器架构
./build.sh --universal     # 发布用：arm64 + x86_64 通用二进制
open ../电池管家.app
```

默认构建缓存在本目录 `.build`。可通过 `IA_BUILD_DIR` 环境变量指定其他构建缓存目录，或通过 `IA_APP_DEST` 指定待验证应用的输出路径。构建脚本默认生成相邻目录的 `电池管家.app`，并进行本地 ad-hoc 签名。没有联网依赖。`IA_UNIVERSAL=1 ./build.sh` 等价于 `--universal`。

发布用的 `.app` 与压缩包必须用 `--universal` 构建：脚本会交叉编译 `arm64` 与 `x86_64`，拷贝后校验二进制确实同时包含两种架构（缺失时以非零状态退出）。只含 `arm64` 的包在 Intel Mac 上无法启动，而 `Info.plist` 的最低系统版本是 macOS 13，发布包需要覆盖这一范围。交叉编译时出现 `x86_64 architecture is deprecated for your deployment target` 属于 Xcode 对旧架构的提示，不影响产物；两种架构的 `minos` 都是 13.0。

```sh
../电池管家.app/Contents/MacOS/BatteryCare --self-test
../电池管家.app/Contents/MacOS/BatteryCare --render-qa /tmp/battery-care-render
../电池管家.app/Contents/MacOS/BatteryCare --render-power-qa /tmp/battery-care-power-render
../电池管家.app/Contents/MacOS/BatteryCare --render-care-qa /tmp/battery-care-care-render
../电池管家.app/Contents/MacOS/BatteryCare --render-protection-qa /tmp/battery-care-protection-render
../电池管家.app/Contents/MacOS/BatteryCare --render-status-qa /tmp/battery-care-status-render
```

`--self-test` 读取真实数据，检查范围、无效充电上限的拒绝、菜单面板的全屏窗口配置及多显示器定位，不提交有效充电写入。`--render-qa` 渲染应用自身界面，绕过桌面屏幕捕捉；毛玻璃背景、原生滚动和控件使用等效静态绘制以便检查布局。正常运行时保留原生控件。`--background` 仅启动菜单栏；`--preview` 明确启用隔离的演示数据，普通启动始终读取本机数据。

## 代码结构

- `AppIdentity.swift`：应用显示名称；系统标识和偏好保持稳定，改名后保留原有设置。
- `Application.swift`：应用生命周期、状态栏、设置窗口和只读检查。
- `DashboardPanel.swift`：不激活主应用的菜单浮层，支持其他应用的全屏空间、多显示器定位及外部点击／Esc 收起。
- `AppModel.swift`：持久化偏好、通知、登录项、充电控制与临时上限恢复。
- `BatteryMonitor.swift`：后台 IOKit 采样、功率历史、固定参数进程 CPU 查询与应用图标。
- `BatterySamplingPolicy.swift`、`BatterySamplingChecks.swift`：仪表盘可见性、采样节流、进程超时与取消、指标校验，以及注入提供者的 monitor 生命周期检查。
- `BatteryTemperature.swift`：区分摄氏度与百分之一摄氏度，校验实时温度并过滤缺失／异常值。
- `BatteryLevelPalette.swift`：菜单栏和仪表盘共用的四档电量配色，未知电量使用中性色。
- `StatusReadout.swift`：实际电量填充、电池内部闪电标志与四档图标配色；充电文字使用绿色，非充电文字保留系统自动对比度。
- `StatusReadoutChecks.swift`：菜单栏图标的电量填充、缺失读数、模板对比度检查与独立渲染。
- `DesignSystem.swift`：石墨灰／薄荷绿视觉系统、材质、卡片、图标、开关与分段控件。
- `SettingsView.swift`：六个设置页面。
- `DashboardView.swift`：实时仪表盘、快捷养护、电池详情与控制能力说明。
- `PowerFlowDiagram.swift`：适配器、系统使用、电池三路功率；充电与电池供电时显示对应方向，未提供的数值保留为空。
- `QuickCareCard.swift`、`QuickCareState.swift`：常用上限、临时充满、恢复系统管理；按真实系统状态标记当前选择，说明与反馈就近显示。
- `ProtectionCard.swift`、`ProtectionState.swift`：实时温度、系统温控、可选高温提醒、实际系统上限和睡眠充电能力，区分未知与关闭状态。
- `TemperatureReminderGate.swift`、`TemperatureReminderChecks.swift`：纯状态温度提醒门控及行为检查；无通知、权限或硬件调用。
- `NotificationPermissionRefresh.swift`、`NotificationPermissionRefreshChecks.swift`：后台通知权限刷新节流、请求去重、超时和旧回调作废。
- `ReminderDelivery.swift`、`ReminderDeliveryChecks.swift`：低电量与上限提醒的提交状态、失败重试，以及跨进程保存的每日民用日期去重。
- `RenderingChecks.swift`：开发阶段组件渲染。
- `ChargeLimitControl.swift`、`ChargeLimitOptions.swift`：系统支持值、拖动松手提交、加减与无障碍调整，界面草稿与实际回读分开。
- `Native/NativeChargeBridge.m`：可选系统充电上限桥接。
- `ChargeState.swift`：待确认动作、偏好值边界、原子临时恢复记录与隔离状态检查。

## 实际能力和边界

菜单栏与设置使用实际电量、电源状态、循环次数、容量估算及系统可提供的实时功率。温度或其他传感器缺失时为空。应用排序百分比是 `ps` 的 CPU 使用率参考，不是耗电份额。

温度读取覆盖 IOPS 摄氏度、`AppleSmartBatteryPack.BatteryData.Temperature` 和旧版 `AppleSmartBattery.Temperature`；Registry 数值按百分之一摄氏度转换。macOS 27 的独立电池包节点读取路径已通过实机验证。没有用历史平均值补出实时温度，也没有增加 SMC 调用。新节点与单位经过实机只读核对，并参考 [SystemInfoKit 的 macOS 27 读取路径](https://github.com/Kyome22/SystemInfoKit/blob/main/Sources/SystemInfoKit/Repositories/BatteryRepository.swift) 和 [Stats 的温度读取实现](https://github.com/exelban/stats/blob/master/Modules/Battery/readers.swift)。

实时功率分流上方展示适配器和系统使用，下方展示电池支路。充电时箭头朝向电池；未接电源时，电池支路朝向系统。接电但未充电时，不推测未验证的电池功率方向。三路功率独立读取，缺失值为“—”，不使用相减方式补出缺失的功率。`--render-power-qa` 单独渲染这一组件的当前实测、充电、电池供电、读数缺失和宽窗口布局，示意状态不改变硬件。

快捷养护位于充电上限下方。80%／90% 按钮直接应用系统上限，选中标记依据系统回读，滑块松手或加减按钮也会立即提交，并以系统回读显示实际上限。未接电源时仍可设置上限；临时 100% 需已接电、电量低于 100% 且能读取原设置。临时模式期间其他上限与系统管理入口禁用，保留“恢复原设置”按钮；重复启动不会覆盖恢复点，恢复失败允许重试，读取失败不会清除待恢复记录。已确认的外部充电设置变更会结束临时跟踪，避免覆盖外部选择。暂停、主动放电和校准收进功能说明。`--render-care-qa` 渲染当前实测、80% 已应用、临时充满、未接电、读数未知、不支持控制等状态，所有按钮使用空回调；`--self-test` 另核对开始条件和临时模式的共享入口保护，不写入有效硬件设置。

菜单浮层使用预先配置的非激活 `NSPanel`，通过 macOS 13 起的 [`canJoinAllApplications`](https://developer.apple.com/documentation/appkit/nswindow/collectionbehavior-swift.struct/canjoinallapplications) 进入其他应用的全屏空间；显示时不激活主应用。浮层高度和位置按点击时状态栏按钮所在的显示器计算。鼠标外部点击、Esc、切换空间或打开设置会收起浮层；鼠标全局监测不申请辅助功能权限。

菜单与设置页均可自由拖动滑块，松手后自动应用，或使用加减按钮逐档调整；不用再点击“应用”。选择值作为界面草稿，不提前写入已应用的设置；界面分别显示目标和系统当前回读，失败或未知状态有就近提示。可用值从系统接口读取，UI 与写入校验共用该列表；本机目前为 80–100% 的 5% 步进，不能承诺系统未公布的任意整数或低于 80% 的实际上限。本机通过 80% 写入／回读和恢复默认 100% 的测试。桥接加载固定的系统 PowerUI 框架路径，检查方法签名、当前支持值、返回错误，捕获 Objective-C 异常；私有接口会随系统变化，失效时提供系统设置入口。没有 root helper、SMC 写入或管理员授权流程。此工程的桥接是原创代码，未复制其他项目的实现。

临时上限 100% 记录原来的上限和启用状态，达到 100% 后恢复。正常退出也尝试恢复；失败保留待恢复记录。异常关闭时上限可能暂留在 100%，下次打开程序恢复跟踪；用户也可在系统电池设置中调整。优化充电仍决定具体充电时机。

当前系统不提供可用的直接暂停／强制放电／睡眠暂停路径，界面诚实显示为未支持。容量校准与高温保护由系统维护。提醒只在程序运行时生效，权限在用户开启功能时请求。登录项只在用户切换开关时注册。

自动保护采用逐项状态显示。高温提醒是独立的通知功能，默认关闭，提醒值默认 40°C，用户可在“计划与自动化”中设为 35–55°C；这是自定提醒值，不是系统温控阈值。仅使用有效且不超过 120 秒的温度，连续两次不同时间的采样达到提醒值才提交通知。同一次升温成功提醒一次；连续两次降至提醒值以下 3°C 后重新监测，成功通知至少相隔 10 分钟，最近成功时间保存在本机。发送失败至少间隔 60 秒重试，关闭提醒或修改阈值会作废旧候选，未知数据不当作降温。用户开启时才请求首次权限；提交前确认权限，区分横幅、通知中心和声音能力。应用退出或 Mac 睡眠时不持续监测，提醒不更改充电和风扇。系统上限根据实际回读区分已应用、系统默认、临时 100% 和状态待确认。`--render-protection-qa` 用空回调核对当前读数、提醒开启、高温、无读数、权限不足、静默通知、临时恢复未知、过期、发送失败和宽布局。全部组件渲染通过仅渲染模式完成，不提交提醒或充电写入。

公开 API 依据 [Apple IOPowerSources](https://developer.apple.com/documentation/iokit/iopowersources_h) 和 [SMAppService](https://developer.apple.com/documentation/servicemanagement/smappservice)。系统充电上限行为见 [Apple Support](https://support.apple.com/en-us/102338)，当前私有充电路径的兼容性研究参考 [batt 的 PowerUI 工程](https://github.com/charlie0129/batt/tree/master/pkg/powerui) 与其 [macOS 27 兼容性说明](https://github.com/charlie0129/batt#macos-27-firmware-with-gated-charge-keys-adapter-mode)。
